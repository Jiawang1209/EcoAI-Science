# 按安装记录四步引导

用户要求每次新安装、重新覆盖安装均从四步引导的第一步开始。系统钥匙串或 Windows DPAPI 能恢复旧凭证时，也不能自动关闭引导。只由用户主动完成或跳过结束本次引导；同一次安装的日常重启沿用该决定。用户进一步明确：应用内自动更新保留已完成状态，手动重新安装才重新引导。

旧版过渡：用户明确接受已经发布的旧版首次升级到这一版时再显示一次引导。旧版没有唯一安装事务记录，无法严格区分自动更新与保留旧数据的手动替换；不以历史备份目录或日志启发式跳过新安装。这一版之后的应用内自动更新保留已完成状态。

安装身份由主进程在首个窗口创建前确定，通过 sandbox preload 的只读字段交给界面，不等待后端或凭证。macOS 使用安装包目录、可执行文件和主入口的文件身份（含路径、inode、创建及修改时间），覆盖安装同版本也变化；App Translocation 时先解析原始安装路径再取身份。Windows NSIS 手动安装时生成新的 GUID 文件；应用内更新明确传入 --updated，从专用注册表值恢复原 GUID。便携版本按原始 exe 身份判断，不能使用每次运行都变化的解压临时目录。开发启动沿用旧的存储键，提供仅开发态测试用的安装身份覆盖。

macOS/Linux 自动换包成功后、重启前，在用户目录保存新物理安装身份到旧引导作用域的绑定；失败/回滚不写绑定。日常启动只在当前物理身份精确匹配该绑定时继承作用域，之后手动重装会有新物理身份，仍从第一步开始。绑定不包含凭证，也不写入已签名的安装包。

打包界面在 localStorage 中按安装身份记录引导完成/跳过，不继承旧版全局标记，也不清理旧标记、会话、凭证和解释器设置。引导首次显示即保持到明确操作，默认欢迎页；已有有效 key 在第三步显示已配置，可直接下一页，不强迫重新填写。读安装身份失败时采用本进程临时身份，优先显示引导并记录普通诊断，不使应用打不开。

验收：新安装存在旧完成记录和有效凭证仍从欢迎页开始；钥匙串核验成功不消失；四步全部可走；同安装完成后重启不重复；同版本替换安装后重新从第一步开始；Windows 安装 GUID 变更能重置状态、NSIS hook 可编译。覆盖相关单元、全量 UI、Electron、类型和构建，并以隔离 macOS 打包实例验证实际 preload/安装身份链路。Windows 无真实主机时明确区分逻辑/编译验证与实机证据。

独立只读审查指出并已修正 App Translocation 的临时挂载不稳定问题；解析原始安装路径后取文件身份，无法解析时保守回到引导，不阻止启动。审查指出的旧版首次升级过渡已由用户明确接受。
